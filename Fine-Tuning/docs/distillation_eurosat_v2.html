# Petit CNN convolutif, entraîné de zéro. Prend le même 224x224 normalisé que le teacher.
class SmallCNN(nn.Module):
    def __init__(self, num_classes, width=STUDENT_WIDTH):
        super().__init__()
        def block(c_in, c_out):
            return nn.Sequential(
                nn.Conv2d(c_in, c_out, kernel_size=3, stride=2, padding=1, bias=False),
                nn.BatchNorm2d(c_out),
                nn.ReLU(inplace=True),
            )
        self.features = nn.Sequential(
            block(3, width),            # 224 -> 112
            block(width, 2 * width),    # 112 -> 56
            block(2 * width, 4 * width),#  56 -> 28
            block(4 * width, 8 * width),#  28 -> 14
        )
        self.pool = nn.AdaptiveAvgPool2d(1)
        self.classifier = nn.Linear(8 * width, num_classes)

    def forward(self, x):
        x = self.features(x)
        x = self.pool(x).flatten(1)
        return self.classifier(x)

01 — Teacher et Student

La distillation entraîne un modèle Student à reproduire les connaissances d'un Teacher déjà entraîné. Le Student est souvent plus petit, mais ce n'est pas une obligation. On ne copie pas nécessairement les poids : on transmet un comportement.

02 — Logits et softmax

Les logits sont les scores bruts de la dernière couche. Ils peuvent être négatifs et ne sont pas normalisés. Le softmax les transforme en probabilités dont la somme vaut 1.

03 — Température

pi(T) = exp(zi/T)Σj exp(zj/T)

Une température positive modifie les écarts entre les logits sans changer leur ordre. T = 1 correspond au softmax classique ; T > 1 adoucit la distribution ; 0 < T < 1 la rend plus tranchée. Une température très élevée tend vers une distribution uniforme.

Lire la formule, étape par étape

zi est le logit de la classe i ; j parcourt toutes les classes (10 pour EuroSAT). T est un scalaire sans unité, identique pour toutes les classes. On divise chaque logit par T, on applique l’exponentielle, puis on normalise par la somme des exponentielles. Le résultat est positif et sa somme vaut 1.

z = [5 ; 3 ; 0,3] → z/4 = [1,25 ; 0,75 ; 0,075] → softmax → [52,1 % ; 31,6 % ; 16,1 %] (environ)

Le rapport de deux probabilités vaut exp((zi − zj)/T). Ainsi, entre les deux premiers logits, le rapport vaut exp(2) ≈ 7,39 à T=1, mais exp(0,5) ≈ 1,65 à T=4. La température réduit les écarts relatifs, sans changer la classe gagnante pour T positif.

ValeurEffet
0 < T < 1Accentue les différences ; vers 0 positif, concentration sur les maxima (partagée en cas d’égalité).
T = 1Softmax ordinaire.
T > 1Adoucit la distribution ; vers l’infini, 1/K pour K classes.
T = 0Interdit : division par zéro.
T < 0Mathématiquement calculable, mais inverse le classement : le plus petit logit devient le plus probable. Inadapté à la distillation classique ; on impose T > 0.

Où intervient T dans le notebook ?

Même image
Teacher → logits → division par T → softmax P
Student → logits → division par T → log-softmax Q
→
KL × T²

En parallèle, les logits bruts du Student vont directement dans cross_entropy avec les vrais labels : cette branche reste à T=1. La température ne modifie ni les poids ni l’architecture du Teacher. Elle agit pendant le calcul de la loss, avant la rétropropagation. En validation et production, on utilise normalement les logits bruts (argmax) ou le softmax à T=1.

Dans le slider suivant, les trois classes sont fictives. Observe notamment T=0,5, 1, 4 et 10 : la classe gagnante reste la même, mais les classes secondaires deviennent visibles. T=4 est le choix du notebook, pas une valeur universelle. Tester sur validation ; trop de chaleur peut masquer les différences utiles.

Softmax personnalisé from scratch

On soustrait le maximum avant l'exponentielle pour améliorer la stabilité numérique. La température peut être un attribut modifiable d'une couche personnalisée.

Keras

class TemperatureSoftmax(keras.layers.Layer):
    def __init__(self, temperature=1., **kwargs):
        super().__init__(**kwargs)
        self.temperature = temperature

    def call(self, logits):
        z = logits / self.temperature
        z = z - ops.max(z, axis=-1, keepdims=True)
        e = ops.exp(z)
        return e / ops.sum(e, axis=-1, keepdims=True)

layer = TemperatureSoftmax(3.)
probs = layer(logits)

PyTorch

class TemperatureSoftmax(nn.Module):
    def __init__(self, temperature=1.):
        super().__init__()
        self.temperature = temperature

    def forward(self, logits):
        z = logits / self.temperature
        z = z - z.amax(dim=-1, keepdim=True)
        e = z.exp()
        return e / e.sum(dim=-1, keepdim=True)

layer = TemperatureSoftmax(3.)
probs = layer(logits)

En distillation, mieux vaut généralement conserver les logits en sortie du modèle et appliquer T dans la loss. On peut alors utiliser T = 1 pour les vrais labels et T > 1 pour comparer Teacher et Student. Les exemples supposent T strictement positive. Cross-entropy

Lhard = − Σᵢ yᵢ log(pᵢ)

Mesure l'erreur par rapport au véritable label. Les fonctions utilisées ci-dessous acceptent les logits directement.

Pour une image, y est un vecteur one-hot (1 pour la vraie classe, 0 ailleurs) et p est le softmax des logits du Student à T=1. La somme se réduit donc à −ln(pvraie classe). Si la vraie classe est Forêt : p=0,9 donne 0,105 ; p=0,6 donne 0,511 ; p=0,1 donne 2,303. Plus la probabilité correcte est faible, plus la pénalité est grande. La moyenne est ensuite calculée sur le batch.

La CE sert à entraîner le Teacher sur les annotations, le Student témoin sans distillation, et la branche hard du Student distillé. Elle peut aussi accepter des cibles probabilistes dans une formulation adaptée. Dans PyTorch, F.cross_entropy reçoit ici des logits et des indices entiers ; ne pas appliquer softmax avant.

KL divergence

KL(P || Q) = Σᵢ Pᵢ log(Pᵢ / Qᵢ)

P est la distribution du Teacher, Q celle du Student. La KL est non négative, non symétrique et vaut zéro lorsque les distributions sont identiques.

P = softmax(logits Teacher/T), Q = softmax(logits Student/T). Chaque terme compare la probabilité donnée par le Teacher à celle du Student : si Q sous-estime une classe importante pour P, le rapport P/Q augmente. Un terme individuel peut être négatif, mais la somme est toujours positive ou nulle. Si P est positif et Q nul, la divergence est infinie (en pratique, log_softmax améliore la stabilité).

La KL est utilisée pendant chaque batch de distillation, après les deux forward et avant backward. Le Teacher est fixe. Sans annotations, on peut utiliser uniquement cette branche ; avec annotations, on combine CE et KL. Une cross-entropy à cibles souples peut remplacer KL car CE(P,Q) = H(P) + KL(P||Q), où H(P) = −Σ Pᵢ ln Pᵢ est constante par rapport au Student.

Exemple : P=[0,85 ; 0,14 ; 0,01], Q=[0,60 ; 0,30 ; 0,10]. La KL vaut 0,85 ln(0,85/0,60) + 0,14 ln(0,14/0,30) + 0,01 ln(0,01/0,10) ≈ 0,1664 nat. Elle n’est pas une accuracy ni un pourcentage.

Comment lire le slider : à 0 %, Q est la prédiction initiale fictive [60,30,10] ; P reste [85,14,1]. À 50 %, Q=[72,5 ; 22 ; 5,5] %. À 100 %, Q=P et KL=0. En entraînement réel, Adam modifie les poids, les probabilités évoluent de façon non linéaire et la KL ne baisse pas nécessairement à chaque batch. Même KL=0 ne prouve pas que la prédiction est correcte : le Teacher peut se tromper.

Alpha : pondérer les deux objectifs

Les coefficients ne sont pas les contributions réelles au gradient. Dans ce notebook, alpha pondère le terme soft : 0,7 = 70 % de KD et 30 % de CE.

Pourquoi T² ?

Le gradient de la KL par rapport au logit du Student est (Qᵢ − Pᵢ)/T. À température élevée, l'écart Qᵢ − Pᵢ diminue lui-même approximativement comme 1/T. Le gradient décroît donc comme 1/T². Multiplier la KL par T² compense cette diminution approximative.

D’où vient Qᵢ − Pᵢ ? Dérivation du gradient

On note sᵢ le logit brut du Student. P est fixe et Q dépend de s. On dérive la KL non multipliée par T² pour un exemple.

KL = Σⱼ Pⱼ ln Pⱼ − Σⱼ Pⱼ ln Qⱼ

Le premier terme est constant. En développant le log-softmax :

ln Qⱼ = sⱼ/T − ln(Σₖ exp(sₖ/T))
∂ ln Qⱼ / ∂ sᵢ = (δᵢⱼ − Qᵢ)/T

δᵢⱼ vaut 1 si i=j, 0 sinon. La dérivée du premier terme du log-softmax donne δᵢⱼ/T ; celle du log de la somme donne Qᵢ/T.

∂ KL / ∂ sᵢ = −Σⱼ Pⱼ(δᵢⱼ − Qᵢ)/T = (Qᵢ Σⱼ Pⱼ − Pᵢ)/T = (Qᵢ − Pᵢ)/T

Car Σ Pⱼ = 1. Si Qᵢ > Pᵢ, le gradient est positif et la descente de gradient tend à diminuer le logit ; si Qᵢ < Pᵢ, elle tend à l’augmenter. Exemple : 0,60−0,85=−0,25 ; à T=4, le gradient vaut −0,0625 avant pondération et moyenne du batch. Les logits sont couplés par le softmax et les poids partagés : ce n’est pas une mise à jour indépendante de chaque probabilité.

À grande T, pour K classes et des logits fixes, softmax(s/T) ≈ 1/K + (sᵢ−moyenne(s))/(KT). Ainsi Q−P est d’ordre 1/T, puis le facteur 1/T de la dérivée donne 1/T². C’est une approximation à haute température, pas une égalité universelle. Avec T², le gradient de la branche soft devient T(Qᵢ−Pᵢ), avant alpha et la moyenne du batch.

PyTorch attend les log-probabilités du Student en premier argument. Les labels y sont des indices entiers de classes.

La loss exacte du notebook

kl_div = nn.KLDivLoss(reduction="batchmean")   # "batchmean" : la vraie moyenne par exemple

def distillation_loss(student_logits, teacher_logits, targets, T, alpha):
    # KLDivLoss attend : 1er argument en log-probabilités, 2e en probabilités.
    #   -> student en log_softmax, teacher en softmax. L'ordre n'est PAS interchangeable.
    soft_student = F.log_softmax(student_logits / T, dim=1)
    soft_teacher = F.softmax(teacher_logits / T, dim=1)
    soft_loss = kl_div(soft_student, soft_teacher) * (T * T)   # <-- le facteur T^2, crucial

    hard_loss = F.cross_entropy(student_logits, targets)       # garde-fou vérité terrain
    return alpha * soft_loss + (1.0 - alpha) * hard_loss

dim=1 correspond à la dimension des classes pour un tenseur [batch, 10]. batchmean divise la somme par la taille du batch, contrairement à mean qui divise aussi par le nombre de classes. À T=4, T²=16. La CE utilise les logits non adoucis.

05 — Entraînement et évaluation

Pour chaque batch, calculer les logits du Teacher sans gradient, calculer ceux du Student, combiner les deux pertes puis mettre à jour uniquement le Student.

Keras (backend TensorFlow)

import tensorflow as tf
teacher.trainable = False
optimizer = keras.optimizers.Adam()
T, alpha = 4., 0.7

for x, y in dataset:
    t = teacher(x, training=False)
    with tf.GradientTape() as tape:
        s = student(x, training=True)
        hard = keras.losses.SparseCategoricalCrossentropy(
            from_logits=True)(y, s)
        soft = keras.losses.KLDivergence()(
            ops.softmax(t/T, axis=-1),
            ops.softmax(s/T, axis=-1))
        loss = (1-alpha)*hard + alpha*T**2*soft
    variables = student.trainable_variables
    grads = tape.gradient(loss, variables)
    optimizer.apply_gradients(zip(grads, variables))

Boucle exacte train_student
def train_student(use_distillation, seed=0):
    set_all_seeds(seed)                       # même init + même ordre de données dans les deux cas
    student = SmallCNN(num_classes).to(device)
    optimizer = torch.optim.Adam(student.parameters(), lr=LR_STUDENT)
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=EPOCHS_STUDENT)
    teacher.eval()                            # figé : il ne fait que fournir des soft targets
    history = []

    t0 = time.time()
    for epoch in range(1, EPOCHS_STUDENT + 1):
        student.train()
        running = 0.0
        for x, y in train_loader:
            x, y = x.to(device), y.to(device)
            optimizer.zero_grad()
            student_logits = student(x)                      # forward student

            if use_distillation:
                with torch.no_grad():                        # teacher figé, pas de graphe
                    teacher_logits = teacher(x)              # MÊME entrée que le student
                loss = distillation_loss(student_logits, teacher_logits, y, T, ALPHA)
            else:
                loss = F.cross_entropy(student_logits, y)    # témoin : vraies étiquettes seules

            loss.backward()
            optimizer.step()
            running += loss.item() * x.size(0)
        scheduler.step()
        history.append(running / len(train_idx))
        if epoch % max(1, EPOCHS_STUDENT // 6) == 0 or epoch == 1:
            print(f"[{'KD' if use_distillation else 'CE'}] epoch {epoch:>2}/{EPOCHS_STUDENT} | "
                  f"loss {history[-1]:.3f} | val acc {accuracy(student, val_loader):.3f}")
    return student, history, time.time() - t0

@torch.no_grad()
def latency_ms(model, n_iter=50, n_warmup=10):
    model.eval()
    x = torch.randn(1, 3, 224, 224, device=device)
    for _ in range(n_warmup):                 # warm-up : on jette les premières passes
        model(x)
    if device.type == "mps":  torch.mps.synchronize()
    elif device.type == "cuda": torch.cuda.synchronize()
    t0 = time.time()
    for _ in range(n_iter):
        model(x)
    if device.type == "mps":  torch.mps.synchronize()
    elif device.type == "cuda": torch.cuda.synchronize()
    return (time.time() - t0) / n_iter * 1000.0

LCM-LoRA

Rappel : comment fonctionne un modèle de diffusion ?

À l’entraînement, on ajoute progressivement du bruit à une image (ou à sa représentation latente). Un réseau apprend à prédire le bruit ou une quantité équivalente à partir du latent bruité, du niveau de bruit et éventuellement du texte. Dans Stable Diffusion, un VAE encode/décode les images, un encodeur de texte fournit le conditionnement et un U-Net réalise les prédictions de débruitage. Le scheduler détermine les niveaux de bruit et les mises à jour.

Image / latent propre
→
Ajout de bruit (entraînement)
→
Latent bruité

En génération, on part d’un bruit aléatoire, puis on appelle le réseau à plusieurs niveaux de bruit pour construire un latent cohérent avec le prompt. Le VAE décode le latent final en image. Les appels répétés au réseau coûtent du temps.

Ce que la distillation change : moins de pas

Un modèle de consistance latent (LCM) apprend à prédire une représentation proche du résultat propre à partir de points différents d’une même trajectoire de débruitage du Teacher. La cible de consistance rapproche les prédictions à des niveaux de bruit différents, avec une cible obtenue via la dynamique du modèle professeur et un modèle cible selon la méthode. Il ne s’agit pas de la CE/KL sur des classes d’EuroSAT. Le Student peut effectuer de grands sauts et générer en quelques évaluations du réseau.

Les points représentent des étapes, pas une mesure de qualité. Réduire les pas d’un modèle standard ne suffit pas à reproduire un LCM.

Rappel : LoRA (Low-Rank Adaptation)

Au lieu de modifier toute une matrice W de taille d×k, on garde W gelée et on apprend deux petites matrices A (r×k) et B (d×r), avec r faible. La couche utilise W + ΔW, où ΔW = (αLoRA/r) BA. Le coefficient LoRA est distinct d’alpha dans la loss EuroSAT. Pour W de 1024×1024 et r=8, A et B totalisent 16 384 paramètres au lieu de 1 048 576 (64 fois moins pour cette matrice). LoRA réduit les paramètres à entraîner et à stocker dans l’adaptateur, pas nécessairement la taille du modèle de base ni le coût de chaque forward.

LCM-LoRA : combiner consistance et adaptation légère

LCM désigne l’apprentissage de la génération en peu de pas ; LoRA désigne le moyen de stocker les modifications de poids sous forme d’adaptateur. LCM-LoRA combine les deux : on entraîne un adaptateur avec un objectif de distillation de consistance, puis on le charge sur un modèle compatible. Le notebook ne réalise pas cet entraînement : il charge un adaptateur déjà distillé pour SD 1.5, remplace le scheduler par LCMScheduler et génère en 4 pas avec guidance 1,5 contre 25 pas et guidance 7,5. Le même prompt et la même seed facilitent la comparaison, mais ne garantissent pas des images identiques. Le gain vient surtout du nombre réduit d’appels au réseau, pas d’une réduction de taille du U-Net.
